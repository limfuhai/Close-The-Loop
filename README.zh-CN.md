# Close the Loop

[English](README.md)

**无需人类看管、能够持续自主工作的 AI 智能体：因为它们会对照现实核查自己的记忆。**

Close the Loop 是漩涡智能（Xuanwo AI）推出的开源智能体系统。它的智能体可以自行设定唤醒时间，以书面形式记录自己认为尚待完成的事项及其依据，并由一个独立的智能体在采取行动之前，对照真实世界核查这些判断。一切都在您自己的电脑上运行，使用您自己的模型密钥和邮箱。

---

## 问题所在

当今的智能体仍然需要人类来把关。智能体长时间独立工作时，它给自己留下的笔记会逐渐偏离现实：它“记得”发过一封其实从未发出的邮件，或者“记得”一场早已取消的会议，然后依据这些错误的判断采取行动。更好的记忆无法解决这个问题，因为记忆系统记录错误判断时，与记录正确判断一样忠实。

因此，所有智能体产品都让人类留在环节之中。智能体可以按计划被触发，但还不能被信任去主导自己的工作。

## 我们的思路

Close the Loop 新增了三个智能体，各自负责一个问题：

- **调度智能体（Scheduler）负责“何时”。** 智能体可以为自己设定唤醒时间。到点后，它会带着自己留下的消息醒来并继续工作，就像您亲自输入了这条指令。唤醒任务注册在 Windows 任务计划程序中，因此即使应用已关闭也会触发；电脑休眠期间错过的唤醒会延后执行，而不会被遗漏。
- **账本智能体（Ledger）负责“做什么”和“为什么”。** 它撰写指令（directive）：具体的未来行动，每一条都以确切证据为依据，例如邮件的 Message-ID 或文件路径。账本是您电脑上的一个文件夹，由带日期、只追加不修改的文件组成，因此记录不会随对话消失。
- **审计智能体（Auditor）负责“是否依然属实”。** 在任何行动依据某条指令执行之前，审计智能体都会对照智能体自身笔记之外的记录进行核查，例如您的已发送邮件、收件箱和磁盘上的文件。它对每条指令给出一个结论：已确认、已过时、相矛盾或无法核实。账本智能体随后执行该结论，关闭被证明为错误的指令。

笔记永远不能作为自身的证据。没有附带证据的“已确认”结论会被记录为“无法核实”；智能体为自己撰写的指令一开始只拥有“可撤销”权限：可以起草，但绝不能发送。

## 实证：一个人为植入的错误判断

我们告诉系统有两封邮件已经发出：一封标题为“Scheduler test”，确实已经发出；另一封标题为“Q4 budget figures”，实际上从未发出。

账本智能体不加判断地记录了两者。审计智能体检索了真实的 Gmail 已发送邮件文件夹，先后三次扩大检索时间范围，通过 Message-ID 确认了第一封邮件，并且没有找到第二封邮件的任何痕迹。账本智能体随后关闭了这条错误的指令。一个错误的判断进入了记录，经过与现实的核对，最终被清除。

测试进行到一半时，页面被意外刷新。重新运行测试时，账本智能体发现自己的指令和审计结论都已保存在磁盘上，于是直接继续，没有产生任何重复记录。记录保存在电脑上，而不是保存在对话里。

## 工作原理

Boundary 的智能体循环运行在本地服务器上。总结智能体（Summarizer）解读请求，规划智能体（Planner）选择下一个执行器，执行器完成一项工作，循环往复直至任务完成。相互独立的工作可以由并行的子智能体同时执行。

对规划智能体而言，调度、审计和账本智能体都是普通的执行器。在其内部，审计智能体和账本智能体各自在主规划智能体之下运行自己的循环，在完成之前调度其他执行器和子智能体收集证据。

任何涉及您电脑的操作都通过**桥接程序（bridge）**进行。这是一个无任何依赖的小型 Python 脚本，在终端中运行即可。邮件直接通过 IMAP 和 SMTP 从您的电脑收发，因此任何支持应用专用密码的邮箱服务都可以使用。

Close the Loop 保存的所有内容都位于您主目录下的一个文件夹中：

| 路径 | 内容 |
|---|---|
| `~/Boundary/ledger/` | 带日期、只追加的指令与审计结论文件，以及当前索引 `LIVE.md` |
| `~/Boundary/wake/` | 待执行的唤醒任务，以及任务计划程序调用的运行脚本 |
| `~/Boundary/chats/messages.jsonl` | 已保存的对话回复，包括定时唤醒产生的回复 |

## 快速开始

### 环境要求

- Windows 10 或 11（调度功能使用 Windows 任务计划程序）
- Python 3.10 或更高版本
- Node.js 18 或更高版本
- DeepSeek 或 Moonshot（Kimi）的 API 密钥，或两者兼有
- 一个拥有应用专用密码或授权码的邮箱账户（Gmail、QQ 邮箱、163 邮箱等）

### 1. 获取代码

```
git clone https://github.com/limfuhai/close-the-loop.git
cd close-the-loop
pip install -r requirements.txt
npm install
```

### 2. 填写模型密钥

打开 `core/api_client.py`，在文件顶部的 `deepseek_api_key` 和 `moonshot_api_key` 中填入您的密钥。可以只填其中一个，也可以都填：没有密钥的模型会被自动跳过。

### 3. 创建配置文件

将 `.env.example` 复制为 `.env`，将 `.env.local.example` 复制为 `.env.local`，然后填写 `.env`：

- `BRIDGE_TOKEN`：任意一串足够长的随机字符串，是您的服务器与桥接程序之间共享的密钥。可以用以下命令生成：
  ```
  python -c "import secrets;print(secrets.token_urlsafe(32))"
  ```
- `MAIL_ADDRESS` 和 `MAIL_AUTH_CODE`：智能体使用的邮箱账户。邮箱服务商不允许应用使用您的普通密码登录，因此请使用应用专用密码：
  - **QQ 邮箱：** 在 QQ 邮箱设置中开启 IMAP/SMTP 服务，并生成授权码。
  - **Gmail：** 开启两步验证，然后在 Google 账号 → 安全性 → 应用专用密码中创建。

邮箱服务商会根据邮箱地址自动识别。如果使用自建邮件服务器，还需要设置 `MAIL_IMAP_HOST`、`MAIL_IMAP_PORT`、`MAIL_SMTP_HOST` 和 `MAIL_SMTP_PORT`。

### 4. 启动

在第一个终端中运行：
```
python core/compiler.py
```
在第二个终端中运行：
```
npm run dev
```
然后打开 http://localhost:3000。

### 5. 连接桥接程序

点击 **Download Bridge**。在第三个终端中进入文件保存的位置，运行：
```
python bridge.py
```
使用 Close the Loop 期间请保持该窗口开启。

### 6. 试一试

创建一个智能体，然后对它说：

> 3 分钟后，给*您自己的邮箱地址*发一封邮件，主题为“Scheduler test”，内容是来自定时唤醒的未来的你的问候。现在只设置唤醒，其他什么都不要做。

三分钟后，Windows 会唤醒这个智能体，它仅凭过去的自己留下的消息完成发送。

接着试一试植入错误的测试：告诉账本智能体一封您确实发过的邮件和一封您从未发过的邮件，然后让审计智能体对照您的已发送邮件核查两者。您会在 `~/Boundary/ledger/` 中看到那条错误的指令被关闭。

## 局限

- 这是一个早期研究版本。一次成功的运行证明了这个思路可行；只有在大量电脑和复杂邮箱上进行开放测试，才能知道它的效果究竟如何、边界在哪里。
- 调度功能目前仅支持 Windows。
- 桥接程序会在您的电脑上执行本地智能体发送给它的命令。请只在您信任的电脑上运行，并确保 `BRIDGE_TOKEN` 不为他人所知。
- 目前尚不能读取日历，因此审计智能体只能通过邮件往来核查会议安排。

## 未来方向

邮件是第一个试验场。同样的问题，即智能体依据无人核查的判断采取行动，也横亘在今天的 AI 与能在物理世界中工作的机器之间。Close the Loop 是我们的路径：从您邮箱里的智能体，走向机器人上的智能体，在没有人类介入的情况下不断改进自己的工作。
